# 邀友让利返现营销活动需求说明书（微信登录版·最终版）

### 一、需求总览

#### 1. 需求目标

- 核心：实现「机构按课程设返现规则→微信登录用户生成通用邀请码→被邀请新用户用码立减→邀请人按订单完课进度解锁返现」的裂变闭环；

- 关键：以微信登录替代实名验证，开放非获客用户参与权限，邀请码通用不绑课程，按单笔订单独立核算，确保合规、轻量化、数据自动联动。

#### 2. 适用范围

- 用户：平台所有微信授权登录用户（获客/非获客）、微信登录新用户；

- 课程：机构开启「返现功能」的正价课程；

- 模块联动：教务管理模块（课程/完课数据）、预约报名模块（订单/支付/退课）、用户中心（余额/提现）。

### 二、核心定义

|术语|定义|
|---|---|
|获客用户|微信登录且有课程报名/购买记录的用户|
|非获客用户|微信登录但无任何课程报名/购买记录的用户|
|通用邀请码|用户微信登录后生成的专属唯一码，与微信openid绑定，无课程/机构绑定，可用于所有返现课程订单，永久有效（微信注销/账号冻结除外）|
|返现课程|机构创建时开启「返现功能」并设定返现规则的正价课程|
|返现总额|单笔订单课程原价（original_price，即课程定价，不含立减/优惠券）× 对应课程返现比例（按课程独立核算）|
|实际返现|返现总额 - 该订单立减金额（单订单独立计算，多订单累加）|
### 三、核心规则（不可修改，逻辑闭环）

#### （一）返现基础规则（核心保留：按课程设定）

1. 返现配置：机构创建/编辑课程时，自主设置「是否开启返现」「返现比例（3%-15%，默认10%）」，支持批量开启/关闭，不同课程可设不同比例；

2. 返现基数：单笔订单对应课程的「原价（original_price）」，即课程 SKU 的定价，不含立减优惠、不含平台佣金；

3. 返现总额：单笔订单返现总额 = 课程原价 × 对应课程返现比例（系统实时计算）；

4. 返现锁定：新用户支付订单后，系统锁定该订单返现总额，进入「待解锁」状态；

5. 返现解锁：按该订单对应课程的「实际完课课时占比」解锁，100%完课解锁全额实际返现，未完课按比例解锁（例：完课50%，解锁50%实际返现）；

6. 返现兑现：解锁后进入邀请人平台余额，支持「提现（满50元，无手续费）+ 平台课程通用抵扣（无门槛）」二选一，余额无有效期；

7. 提现限制：仅可提现至「登录平台的微信账号零钱」，与微信账号一对一绑定，不可更改；余额满50元可发起提现，提交后系统直接发起微信零钱转账，无需人工审核。

#### （二）邀请码规则（核心优化：微信登录即可生成）

1. 生成权限：所有微信授权登录用户（获客/非获客），登录后在个人中心「一键生成通用邀请码」，无需报名/购课，一个微信账号仅生成一个邀请码；

2. 邀请码管理：用户可自主「复制」邀请码，生成后永久有效，不可冻结/重置；微信注销账号后邀请码自动失效；账号被平台封禁后邀请码失效；

3. 使用规则：通用邀请码可用于平台内所有返现课程订单，同一邀请码可被多笔不同课程订单使用，互不影响；

4. 有效性校验：新用户填写邀请码时，系统校验3点：① 邀请码归属平台微信登录用户；② 当日使用次数未超上限；③ 订单对应课程为返现课程（`cashback_enabled = true`），任一不满足则提示「邀请码无效」；**三个校验均在 `validateInviteCode` 接口中统一完成**，不分散到调用方。

#### （三）邀友让利规则（订单动态核算）

1. 让利设置：邀请人（获客/非获客）可设置「通用让利比例（0%-100%，默认50%）」，适用于所有使用其邀请码的订单，支付前可修改，支付后锁定；

2. 立减核算：新用户填写有效邀请码后，系统实时触发：

① 匹配订单对应课程的返现规则；

② 计算返现总额；

③ 立减金额 = 返现总额 × 邀请人通用让利比例；

1. 立减生效：立减金额直接抵扣本笔订单学费，新用户实付 = 课程原价 - 立减金额 - 其他优惠券（可叠加），立减金额不可拆分、不可提现；

2. 实际返现计算：邀请人实际返现 = 该订单返现总额 - 该订单立减金额（单订单独立计算）。

#### （四）邀请关系与订单核算规则

1. 关系绑定：单笔订单仅可填写1个邀请码，支付后「邀请人微信openid-新用户微信openid-订单」一对一永久绑定，不可修改；同一用户多笔订单可填不同邀请码；

2. 层级限制：仅支持「一级邀请」，邀请人仅可获得直接邀请订单的实际返现，新用户再邀请他人与原邀请人无任何利益关联；

3. 多订单核算：同一邀请码的多笔订单，分别独立完成「返现计算-立减生效-完课解锁-金额累加」，某订单退课/未完课不影响其他订单。

#### （五）退课/改课规则

1. 新用户退课：

    - 未上课退课：立减金额不退还，该订单返现总额作废，邀请人无返现；

    - 已上课退课：按实际完课比例解锁邀请人实际返现，立减金额不退还；

2. 邀请人退课（仅获客用户）：自身退课不影响其已产生的邀请订单返现流程，未解锁的继续按完课进度解锁；

3. 机构改课：

    - 改返现比例：仅对修改后新订单生效，旧订单按原规则核算；

    - 改课时/价格：已支付订单按修改后的课时/实付比例重新核算解锁进度，已解锁返现不追溯。

#### （六）风控规则（微信生态适配，防刷单+合规）

1. 登录风控：平台仅支持「微信授权一键登录」，无其他登录方式，一个微信账号仅对应一个平台账号，杜绝批量注册；

2. 异常账号拦截：系统通过「微信openid+设备号+登录IP+微信支付账号」多维度识别异常：

    - 同一设备登录多个微信账号、生成多个邀请码；

    - 同一微信账号多设备异地频繁登录；

    - 无任何互动（未浏览/收藏/预约课程）但邀请码被大量使用；

    触发以上行为立即冻结相关账号的邀请码、立减、返现权限；

3. 订单/支付风控：


    - 支付后24小时内未完成「课程预约/首次上课签到」的订单，自动冻结立减/返现权益，完成签到后恢复；

4. 邀请行为风控：

    - 单个邀请码单日使用上限50次（平台可配置），超上限当日不可用，次日自动恢复；

    - 拦截同一微信生态关联主体（同一好友关系链、同一社群）的自邀自购/互相邀请，冻结权益且不予退费；

5. 合规限制：强制一级邀请，无多级返现，返现规则全链路公示，数据留存≥1年可追溯。

### 四、多端功能需求

#### （一）机构端（小程序，账号密码登录）

> **已实现功能范围**：机构端当前提供课程管理、订单管理、教师管理、教室管理、排课管理、评价管理，营销相关能力仅限课程级别的返现开关配置。Banner 管理为平台管理员独有，机构端不涉及。

|功能模块|核心功能点|详细需求|
|---|---|---|
|课程管理|返现规则配置|创建/编辑课程时，设置「返现开关（cashback_enabled）」「返现比例（3%-15%，cashback_ratio）」；返现开关关闭的课程，用户使用邀请码无效（系统自动拦截）|

#### （二）用户端（小程序/APP，微信登录）

|功能模块|核心功能点|详细需求|
|---|---|---|
|登录页|微信一键登录|展示「微信登录」按钮，授权后自动登录，无需额外操作，首次登录自动生成通用邀请码|
|个人中心|通用邀请码管理|展示专属邀请码，支持复制；显示邀请码使用次数、累计待解锁返现、累计已解锁返现|
|个人中心|让利比例设置|滑动设置通用让利比例（0%-100%），实时提示「好友立减比例」，修改后未支付订单实时生效|
|个人中心|邀请订单管理|按「待解锁/已解锁/已作废」分类展示订单，单订单显示：课程名称、实付金额、返现总额、立减金额、完课进度、实际返现，支持点击查看完课详情|
|个人中心|余额/提现|展示累计已解锁余额，支持提现（满50元）/课程抵扣；提现申请提交后系统直接发起微信零钱转账，无需人工审核；展示提现状态（处理中/已到账/失败）|
|报名页面|邀请码输入|返现课程订单页显示「填写邀请码立减」入口，支持扫码识别；输入后实时显示本订单立减金额，确认后抵扣学费，仅支持微信支付|
|消息通知|进度提醒|推送4类微信模板消息：① 他人用码下单**并支付成功**（通知邀请人）；② 订单支付成功（待解锁返现，通知邀请人）；③ 完课解锁返现（通知邀请人）；④ 提现到账（通知提现用户）|

|权限管理|机构权限控制|机构仅可查看/操作本机构数据，不可跨机构访问|
### 五、模块联动需求（系统自动触发，无人工干预）

#### 1. 与教务管理模块联动

- 课程返现规则：机构配置的课程返现信息，自动同步至营销模块，作为订单核算依据；

- 完课数据：教师记录的课程课时签到/完课数据，实时同步至对应订单，按比例解锁返现；

- 课程修改：机构修改课程返现比例/课时/价格，自动同步至营销模块，按规则对新/老订单生效。

#### 2. 与预约报名模块联动

- 订单创建：新用户微信登录后填写邀请码，系统自动匹配课程返现规则，实时计算立减金额；

- 支付成功：订单微信支付完成后，自动锁定邀请关系、返现总额、立减金额，生成邀请订单记录；

- 退课申请：新用户发起退课，系统按退课规则处理对应订单返现，更新邀请订单状态。

#### 3. 与用户中心模块联动

- 微信登录：用户微信授权登录后，自动解锁邀请码生成、立减参与权限，首次登录自动生成邀请码；

- 余额更新：返现解锁后，自动累加至用户余额；提现成功后，实时扣减余额，同步推送微信到账通知；

- 账号状态：用户微信注销账号，邀请码失效，未解锁返现作废；账号被冻结，暂停返现解锁/提现。

### 六、非功能需求

#### 1. 性能要求

- 核心操作响应时间≤1秒（微信登录、邀请码校验、立减计算、返现解锁）；

- 支持峰值2000+用户同时微信登录/下单/分享，数据无卡顿、无交叉误差；

- 多订单并发核算时，余额实时更新，无累加误差。

#### 2. 安全要求

- 微信openid、邀请关系、返现流水、提现信息全程加密存储；

- 核心数据（返现总额、完课进度、实际返现）不可篡改，操作日志可追溯；

- 权限隔离：机构/用户仅可查看本人/本机构数据，无跨权限访问。

#### 3. 易用性要求

- 用户操作步骤≤2步（微信登录、生成邀请码、设置让利比例、分享、提现）；

- 规则提示清晰（如「返现需完课，未完课按比例解锁」「提现仅支持微信零钱」）；

- 输入错误有明确提示（如「邀请码无效」「支付金额不足」）。

### 七、合规要求

1. 规则公示：返现规则需在课程详情页、订单支付页、邀请码分享页、个人中心4个位置醒目公示，字体≥12号；

2. 宣传规范：禁止使用「全额返」「零元学」「躺赚」等夸大词汇，需标注「返现需完成对应课时」；

3. 数据留存：所有订单、邀请关系、返现流水、完课数据、提现记录留存≥1年，支持监管核查；

4. 层级限制：技术层面屏蔽多级邀请功能，仅支持一级邀请，规避传销风险；

5. 微信生态合规：严格遵循微信开放平台、微信支付的合规要求，所有授权、支付、消息推送功能符合微信官方规范。


### 案例演示
1. 平台：支持所有注册实名用户生成通用邀请码（不绑课程/机构），仅一级邀请；
2. 机构A：美术类机构，创建2门返现课程，返现规则按课程独立设定（未改核心逻辑）：
- 课程1：少儿美术基础课，原价2000元，开启返现，返现比例10%；
- 课程2：少儿美术进阶课，原价3000元，开启返现，返现比例12%；
3. 三类用户角色（覆盖获客/非获客/新用户）：
- 甲：非获客用户（仅平台注册实名，未报任何课程），生成了个人通用邀请码，设置通用让利比例50%；
- 乙：获客用户（已报机构A的基础课），生成了个人通用邀请码，设置通用让利比例80%；
- 丙/丁：新用户（平台未注册，有美术课报名需求）。
 
案例1：非获客用户甲邀请新用户丙，报名机构A基础课（核心验证：非获客用户参与+课程定返现）
 
步骤1：新用户丙报名操作
 
丙注册平台并实名，在机构A课程页选择美术基础课（2000元），下单时填写非获客用户甲的通用邀请码，系统实时核算：
 
- 匹配课程返现规则：基础课返现比例10%，返现基数为订单实付金额（无其他优惠券，实付2000元）；
- 计算本订单返现总额：2000×10% = 200元；
- 计算立减金额：返现总额×甲的通用让利比例=200×50% = 100元；
- 丙最终实付：2000-100 = 1900元，支付完成后，邀请码与本笔基础课订单一对一绑定，让利比例锁定，甲不可再修改。
 
步骤2：返现解锁（按课程完课进度，核心匹配教务联动）
 
机构A的美术基础课共40课时，完课周期2个月，丙的上课进度直接决定甲的返现解锁比例：
 
1. 丙完成20课时（50%）：系统按课程完课比例解锁50%返现，甲解锁金额=（200-100）×50% = 50元，50元自动进入甲的平台余额（达到提现门槛）；
2. 丙完成40课时（100%）：系统解锁剩余50%返现，甲再解锁50元，累计实际到手返现100元（返现总额200-立减100）；
3. 若丙上完10课时后退课：仅解锁25%返现，甲实际到手=（200-100）×25% = 25元，余额未达提现门槛，可累计至其他订单返现。
 
步骤3：甲的权益兑现
 
甲的平台余额累计100元后，可选择：① 直接提现（T+1到账，无手续费）；② 用余额抵扣平台内任意机构课程学费（无门槛，可叠加优惠券）。
关键：甲全程未报任何课程，仅为非获客用户，仍正常享受返现权益，完全匹配「非获客用户可参与」需求。
 
案例2：获客用户乙邀请新用户丁，先后报名基础课+进阶课（核心验证：通用邀请码+多订单独立核算）
 
前提：乙的通用邀请码可复用，让利比例80%适用于所有订单，两门课程返现规则各自独立（按课程设定）。
 
第一笔订单：丁报名美术基础课（2000元，返现10%）
 
1. 丁下单填写乙的通用邀请码，系统核算：返现总额=2000×10%=200元，立减金额=200×80%=160元，丁实付1840元；
2. 该订单与乙的邀请码绑定，乙本笔订单待解锁实际返现=200-160=40元；
3. 丁完课100%后，乙解锁40元，进入平台余额。
 
第二笔订单：1个月后，丁继续报名美术进阶课（3000元，返现12%）
 
1. 丁下单仍填写乙的同一通用邀请码（无需重新生成），系统按进阶课规则独立核算：返现总额=3000×12%=360元，立减金额=360×80%=288元，丁实付2712元；
2. 该订单与乙的邀请码新的一对一绑定，与上一笔基础课订单无关联，乙本笔订单待解锁实际返现=360-288=72元；
3. 丁进阶课完课100%后，乙解锁72元，累计余额=40+72=112元，可提现/抵扣。
 
关键细节
 
1. 乙的通用邀请码可用于不同课程、多笔订单，无需为基础课/进阶课单独生成邀请码；
2. 两笔订单的返现、立减、解锁完全独立：若丁基础课完课、进阶课退课，仅影响进阶课订单返现，基础课40元仍正常解锁；
3. 两门课程的返现比例由机构A按课程独立设定（10%/12%），系统自动匹配对应课程规则，未做全局统一，保留核心需求。
 
案例3：退课场景
 
新用户丙报名基础课后，上完10课时（25%）申请退课，其他条件同案例1：
 
1. 丙实付1900元，机构按课程剩余课时退费：1900 - （1900÷40×10）= 1425元（仅退未上课部分学费）；
2. 丙下单时的100元立减金额无需退还，平台/机构不做追回；
3. 非获客用户甲仅按丙实际完课比例（25%）解锁返现：（200-100）×25% = 25元，无其他损失；
4. 本笔基础课订单后续返现流程终止，甲的通用邀请码仍可正常用于其他用户/其他课程的订单。
 
案例核心匹配的需求要点
 
1. ✅ 课程定返现规则：返现比例、返现总额由机构按单课程设定，不同课程独立核算，非全局统一；
2. ✅ 非获客用户可参与：未报课的甲仅注册实名，即可生成通用邀请码，邀请下单后正常解锁返现；
3. ✅ 通用邀请码：邀请码不与任何课程/机构绑定，可重复用于多笔不同课程订单，无需单独生成；
4. ✅ 订单动态核算：每笔订单独立匹配对应课程的返现规则，独立计算立减/返现，独立解锁，多订单互不影响；
5. ✅ 一级邀请：仅邀请人（甲/乙）可获得直接邀请订单的返现，丙/丁再邀请他人，与甲/乙无任何利益关联；
6. ✅ 教务联动：返现解锁唯一依据为订单对应课程的实际完课进度，完课多少解锁多少，未完课按比例核算；
7. ✅ 让利自主：邀请人可自主设置通用让利比例，系统按比例计算新用户立减金额，支付后锁定比例，支付前可修改。

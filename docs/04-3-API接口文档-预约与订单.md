## 1. 预约模块 (Booking)

### 1.1 创建试听预约

**接口**: `POST /booking`  
**描述**: 家长预约试听课  
**认证**: 需要 JWT Token (家长用户)

**请求参数**:
```json
{
  "course_id": "3456789012345678",
  "schedule_id": "1234567890123456",
  "student_name": "小明",
  "student_age": 8,
  "parent_phone": "13800138000",
  "remark": "孩子对钢琴很感兴趣"
}
```

**DTO验证规则**:
```typescript
class CreateBookingDto {
  @IsNotEmpty({ message: '课程ID不能为空' })
  @IsString()
  course_id: string;

  @IsNotEmpty({ message: '排课ID不能为空' })
  @IsString()
  schedule_id: string;

  @IsNotEmpty({ message: '学生姓名不能为空' })
  @IsString()
  student_name: string;

  @IsNotEmpty({ message: '学生年龄不能为空' })
  @IsInt()
  @Min(1)
  @Max(100)
  student_age: number;

  @IsNotEmpty({ message: '家长电话不能为空' })
  @IsString()
  @Matches(/^1[3-9]\d{9}$/, { message: '手机号格式不正确' })
  parent_phone: string;

  @IsOptional()
  @IsString()
  remark?: string;
}
```

**响应数据**:
```json
{
  "code": 200,
  "message": "success",
  "data": "5678901234567890"
}
```

**业务逻辑**:
1. 验证课程和排课存在
2. 验证排课是否还有空位（booked_count < max_students）
3. 验证用户是否已预约该排课（同一排课只能预约一次）
4. 创建预约记录（状态：pending）
5. 更新排课的 booked_count + 1

**错误码**:
- `400`: 课程或排课不存在
- `400`: 该排课已满
- `400`: 您已预约该时间段

### 1.8 修改预约排课 ⭐

**接口**: `PUT /booking/:id/change-schedule`  
**描述**: 家长修改预约的排课时段  
**认证**: 需要 JWT Token (家长用户)

**路径参数**:
- `id`: 预约ID

**请求参数**:
```json
{
  "new_schedule_id": "1234567890123457"
}
```

**响应数据**:
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "success": true,
    "needsApproval": false
  }
}
```

**响应字段说明**:
- `success`: 操作是否成功
- `needsApproval`: 是否需要机构审核
  - `false`: 距离上课时间 ≥ 24小时，直接修改成功
  - `true`: 距离上课时间 < 24小时，已提交审核，等待机构处理

**业务逻辑**:
1. 验证用户权限（必须是预约人本人）
2. 验证预约状态为 pending 或 confirmed
3. 验证新排课存在且属于同一课程
4. 验证新排课有剩余名额
5. **判断24小时规则**：
   - 距离当前排课上课时间 ≥ 24小时：直接更新 schedule_id
   - 距离当前排课上课时间 < 24小时：
     - 保存 pending_change_schedule_id
     - 状态改为 pending_change
     - 返回 needsApproval = true

**错误码**:
- `400`: 当前预约状态不允许修改排课
- `400`: 排课不属于当前课程
- `400`: 该时段已满，请选择其他时段
- `404`: 预约不存在
- `404`: 排课不存在

---

### 1.9 审核修改预约请求 ⭐

**接口**: `PUT /booking/:id/review-change`  
**描述**: 机构审核24小时内的修改预约请求  
**认证**: 需要 JWT Token (机构管理员)

**路径参数**:
- `id`: 预约ID

**请求参数**:
```json
{
  "action": "approve",
  "reason": "可选，拒绝时填写原因"
}
```

**action 可选值**:
- `approve`: 同意修改
- `reject`: 拒绝修改

**响应数据**:
```json
{
  "code": 200,
  "message": "success",
  "data": true
}
```

**业务逻辑**:
1. 验证机构权限
2. 验证预约状态为 pending_change
3. 验证 pending_change_schedule_id 存在
4. 根据 action 处理：
   - `approve`：
     - 更新 schedule_id = pending_change_schedule_id
     - 清除 pending_change_schedule_id
     - 状态改为 confirmed
   - `reject`：
     - 清除 pending_change_schedule_id
     - 状态改为 confirmed
     - 记录拒绝原因

**错误码**:
- `400`: 该预约没有待审核的修改请求
- `400`: 找不到待审核的排课信息
- `404`: 预约不存在

## 2. 订单模块 (Order)

### 2.1 创建订单

**接口**: `POST /order`  
**描述**: 家长下单购买课程  
**认证**: 需要 JWT Token (家长用户)

**请求参数**:
```json
{
  "course_id": "3456789012345678",
  "sku_id": "4567890123456789",
  "student_name": "小明",
  "student_age": 8,
  "parent_phone": "13800138000"
}
```

**DTO验证规则**:
```typescript
class CreateOrderDto {
  @IsNotEmpty({ message: '课程ID不能为空' })
  @IsString()
  course_id: string;

  @IsNotEmpty({ message: 'SKU ID不能为空' })
  @IsString()
  sku_id: string;

  @IsNotEmpty({ message: '学生姓名不能为空' })
  @IsString()
  student_name: string;

  @IsNotEmpty({ message: '学生年龄不能为空' })
  @IsInt()
  @Min(1)
  @Max(100)
  student_age: number;

  @IsNotEmpty({ message: '家长电话不能为空' })
  @IsString()
  @Matches(/^1[3-9]\d{9}$/, { message: '手机号格式不正确' })
  parent_phone: string;
}
```

**响应数据**:
```json
{
  "code": 200,
  "message": "success",
  "data": "7890123456789012"
}
```

**业务逻辑 - 订单快照机制** ⚠️：
1. 验证课程和SKU存在且属于同一课程
2. 验证SKU库存充足
3. **创建订单快照**（保存订单创建时的价格和信息）：
   ```json
   {
     "course": {
       "title": "钢琴基础课",
       "cover_url": "https://xxx.com/piano-cover.jpg"
     },
     "sku": {
       "name": "10课时包",
       "total_lessons": 10,
       "total_price": 1000.00,
       "cashback_type": "percentage",
       "cashback_value": 10,
       "online_pay_price": 100.00,
       "offline_pay_price": 900.00
     },
     "institution": {
       "name": "某某艺术培训中心",
       "contact_phone": "010-12345678"
     }
   }
   ```
4. 创建订单记录：
   - `total_price`: 从快照中获取
   - `online_pay_price`: 从快照中获取（需线上支付金额）
   - `offline_pay_price`: 从快照中获取（线下支付金额）
   - `status`: unpaid（待支付）
5. 减少SKU库存 - 1

**快照的意义**:
- 价格变更不影响已生成订单
- 即使课程/SKU被删除，订单仍可查看
- 保留订单创建时的完整信息

**错误码**:
- `400`: 课程或SKU不存在
- `400`: SKU库存不足
- `400`: SKU不属于该课程

### 2.8 处理退款（机构同意）

**接口**: `PUT /order/:id/process-refund`  
**描述**: 机构处理退款（同意退款）  
**认证**: 需要 JWT Token + 机构权限

**路径参数**:
- `id`: 订单ID

**请求参数**:
```json
{
  "action": "approve"
}
```

**响应数据**:
```json
{
  "code": 200,
  "message": "success",
  "data": true
}
```

**业务逻辑**:
1. 验证机构权限
2. 验证订单状态为 refund_pending
3. 更新状态为 refunding（退款处理中）
4. 如有线上支付金额，发起微信退款
5. 退款完成后更新状态为 refunded
6. 关联的未签到预约（pending/confirmed）自动取消

## 3. 签到模块 (Check-in)

### 3.1 上课签到

**接口**: `POST /check-in`  
**描述**: 家长为已购买的课程进行上课签到  
**认证**: 需要 JWT Token (家长用户)

**请求参数**:
```json
{
  "order_id": "1234567890123456",
  "latitude": 39.9042,
  "longitude": 116.4074,
  "remark": "今天学习了新曲目"
}
```

**DTO验证规则**:
```typescript
class CheckInDto {
  @IsNotEmpty({ message: '订单ID不能为空' })
  @IsString()
  order_id: string;

  @IsOptional()
  @IsNumber()
  latitude?: number;

  @IsOptional()
  @IsNumber()
  longitude?: number;

  @IsOptional()
  @IsString()
  remark?: string;
}
```

**响应数据**:
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": "5678901234567890",
    "order_id": "1234567890123456",
    "lesson_no": 3,
    "check_in_time": "2026-02-01T10:30:00.000Z",
    "is_makeup": false,
    "remark": "今天学习了新曲目"
  }
}
```

**业务逻辑**:
1. 验证订单存在且属于当前用户
2. 验证订单状态为 `confirmed`
3. 检查今天是否已签到（每个订单每天只能签到一次）
4. 检查是否还有剩余课时（`completed_lessons < total_lessons`）
5. 创建签到记录，`lesson_no` = `completed_lessons + 1`
6. 更新订单的 `completed_lessons` + 1
7. 如果 `completed_lessons == total_lessons`，自动将订单状态改为 `completed`

**错误码**:
- `400`: 订单不存在
- `400`: 订单状态不正确，只能对已确认订单签到
- `400`: 今天已经签到过了
- `400`: 课时已全部完成
- `403`: 无权限操作此订单

---

### 3.2 补卡签到

**接口**: `POST /check-in/makeup`  
**描述**: 家长为过去某天进行补卡签到  
**认证**: 需要 JWT Token (家长用户)

**请求参数**:

**DTO验证规则**:
```typescript
class MakeupCheckInDto {

  @IsNotEmpty({ message: '补卡日期不能为空' })
  @IsString()
  @Matches(/^\d{4}-\d{2}-\d{2}$/, { message: '日期格式必须为YYYY-MM-DD' })
  makeup_date: string;

  @IsOptional()
  @IsString()
  remark?: string;
}
```

**响应数据**:
```json
{

    "order_id": "1234567890123456",

    "check_in_time": "2026-02-01T10:35:00.000Z",

    "makeup_date": "2026-01-28",
    "remark": "当天忘记签到，现在补签"
  }
}
```

**业务逻辑**:
1. 验证订单存在且属于当前用户
2. 验证订单状态为 `confirmed`
3. 验证补卡日期不是未来日期
4. 检查该日期是否已签到
5. 检查是否还有剩余课时
6. 创建签到记录（`is_makeup = true`）
7. 更新订单的 `completed_lessons` + 1
8. 如果课时全部完成，自动完成订单

**错误码**:
- `400`: 订单不存在
- `400`: 订单状态不正确
- `400`: 补卡日期不能是未来日期
- `400`: 该日期已签到过
- `400`: 课时已全部完成
- `403`: 无权限操作此订单

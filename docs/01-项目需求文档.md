# 稚小苗 项目需求文档

**文档版本**: v1.6  
**创建日期**: 2026年1月17日  
**更新日期**: 2026年2月23日  
**项目名称**: 稚小苗 - 稚小苗管理系统  
**项目类型**: 前后端分离 Web/小程序应用

---

## 1. 项目概述

### 1.1 项目背景

随着素质教育的发展，儿童兴趣培训市场规模不断扩大。培训机构数量众多，但缺乏统一的管理平台；家长查找课程信息困难，预约体验不便；机构运营成本高，获客难度大。**稚小苗** 应运而生，旨在打造一个连接培训机构与家长的综合性平台。

### 1.2 项目目标

#### 1.2.1 业务目标
- 为培训机构提供一站式管理平台（课程、教师、教室、排课）
- 为家长提供便捷的课程浏览、预约、购买、评价服务
- 建立机构与家长之间的信任桥梁
- 提升行业运营效率，降低获客成本

#### 1.2.2 用户价值
- **培训机构**: 降低运营成本、提高管理效率、获取精准客源
- **家长用户**: 节省搜索时间、获得可靠信息、享受优质服务
- **平台方**: 构建行业生态、获得数据价值、实现商业变现

### 1.3 项目范围

#### 1.3.1 核心功能模块
1. 机构管理（入驻审核、信息管理）
2. 课程管理（发布、SKU、分类）
3. 资源管理（教室、教师、排课）
4. 预约管理（试听预约、状态跟踪、修改预约）
5. 订单管理（购买、支付、退款、上课签到）
6. 评价管理（评分、评论、回复）
7. 用户管理（认证、权限、信息）
8. 宝贝管理（添加、编辑、选择）
9. 课表管理（日/周/月视图、课程安排）
10. 首页聚合（Banner、推荐内容）
11. 签到管理（上课打卡、补卡、课时进度）
12. 邀友返现（邀请码、让利分成、余额提现）
13. 微信支付（在线支付、退款、支付回调）

#### 1.3.2 目标用户群体
- **主要用户**: 3-12岁儿童的家长（25-45岁）
- **机构用户**: 儿童稚小苗培训机构（艺术、体育、科技等）
- **平台管理员**: 平台运营人员

#### 1.3.3 支持平台
- **微信小程序**（家长端 + 机构端 + 管理端多角色集成）
  - 统一小程序入口，根据用户角色显示不同功能模块
  - **家长用户**：通过微信一键登录（获取openid）
  - **机构管理员/教师**：通过**微信手机号一键登录**（微信手机号快速验证）
  - **平台管理员**：通过**用户名密码登录**（账号由运营人员通过环境变量 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 配置）
  - 多角色独立入口机制：各角色拥有独立的登录入口，用户根据自身角色进入对应登录页（家长端微信登录、机构/教师端微信手机号登录、管理员端账号密码登录）
- 后期扩展：iOS/Android App、PC 管理后台

## 3. 功能需求

### 3.1 机构管理模块

#### 3.1.1 机构入驻

**需求描述**: 培训机构可以提交入驻申请，填写机构信息并创建账号。

**功能要点**:
- 填写机构基本信息（名称、Logo、简介、联系方式）
- 上传营业执照、法人身份证等资质文件
- 选择经营类目（艺术类、体育类、科技类等）
- 填写详细地址（省市区 + 详细地址）
- 设置机构管理员账号（**手机号**，支持批量添加多个管理员）
- 提交后进入待审核状态
- 可选填写机构展示内容（教师团队、荣誉时刻、精彩瞬间）

**业务规则**:
- 机构名称不可重复
- 营业执照号唯一
- 必须上传营业执照和法人身份证
- 提交后进入 `pending`（待审核）状态
- 审核通过前不可发布课程

**用户故事**:
```
作为培训机构负责人
我想在平台提交入驻申请
以便获得在平台上发布课程的资格
```

#### 3.1.2 机构信息管理

**需求描述**: 机构可以查看和编辑自己的基本信息。

**功能要点**:
- 查看机构详情（名称、Logo、简介、地址、联系方式）
- 编辑普通信息（简介、电话、营业时间、地址等）
- 编辑资质信息受限（营业执照、法人等，审核通过后不可修改）
- 查看审核状态和审核意见
- 查看机构统计数据（课程数、订单数、评分等）

**业务规则**:
- 审核通过后，营业执照、法人等资质信息不可修改
- 草稿状态下，所有信息均可修改
- 冻结状态下，信息只读

#### 3.1.3 机构审核（平台侧）

**需求描述**: 平台管理员可以审核机构入驻申请。

**功能要点**:
- 查看待审核机构列表
- 查看机构详细资料和资质文件
- 通过审核（审核通过）
- 拒绝审核（填写拒绝原因）
- 冻结机构（违规处理）
- 解冻机构

**审核状态流转**:
```
draft（草稿，可选）
  ↓ 提交审核
pending（待审核）
  ↓ 管理员通过
contract_signing（待签约）
  ↓ 机构上传签约凭证
contract_review（签约审核中）
  ↓ 管理员审核通过
approved（已通过，正常运营）
  ↓ 违规冻结
frozen（已冻结）
  ↓ 解冻
approved（恢复正常）

pending（待审核）
  ↓ 管理员拒绝
rejected（已拒绝）
  ↓ 机构修改后重新提交
pending（待审核）

contract_review（签约审核中）
  ↓ 管理员驳回签约
contract_signing（重新待签约）
```

**业务规则**:
- 审核通过（approved）后才能发布课程
- 拒绝后机构可以修改资料重新提交
- 冻结后机构所有人（包括机构用户、教师、平台管理员）均无法登录和操作该机构，机构信息完全只读
- 仅平台管理员可以冻结/解冻机构

#### 3.1.4 位置搜索

**需求描述**: 家长可以根据当前位置搜索附近的培训机构。

**功能要点**:
- 基于用户当前位置（经纬度）搜索附近机构
- 设置搜索半径（默认5km，最大20km）
- 按距离排序
- 显示机构距离用户的距离
- 支持按类目筛选
- 支持按区域搜索（省市区三级联动）

**业务规则**:
- 使用 PostgreSQL PostGIS + `distance_km()` 函数计算距离
- 仅显示审核通过的机构
- 仅显示激活状态的机构

#### 3.1.5 机构展示内容管理

**需求描述**: 机构可以管理展示给家长的内容，包括荣誉证书、精彩瞬间（教学环境/学员作品/活动照片）和教师团队。

##### 3.1.5.1 荣誉时刻管理

**功能要点**:
- 添加荣誉证书（上传证书图片、填写荣誉名称、获奖日期）
- 编辑荣誉信息
- 删除荣誉证书
- 排序调整（拖拽排序）
- 查看荣誉列表

**数据字段**:
- `title`: 荣誉名称（如"2024年度优秀培训机构"）
- `img_url`: 证书图片URL
- `honor_date`: 获奖日期
- `sort_order`: 排序权重（数字越小越靠前）

**业务规则**:
- 荣誉证书图片必须上传
- 荣誉名称不可为空
- 支持最多20个荣誉证书
- 自动按 sort_order 升序排列

**用户故事**:
```
作为机构管理员
我想上传机构获得的荣誉证书
以便增强家长对机构的信任
```

##### 3.1.5.2 精彩瞬间管理

**功能要点**:
- 添加展示图片（上传图片、选择类型、填写描述）
- 编辑图片信息
- 删除图片
- 排序调整（拖拽排序）
- 按类型筛选查看

**图片类型**:
- `classroom`: 教学环境（教室、设施、装修等）
- `student_work`: 学员作品（学员完成的作品、表演等）
- `activity`: 活动照片（机构举办的活动、比赛等）

**数据字段**:
- `title`: 图片标题（可选）
- `img_url`: 图片URL
- `type`: 类型（classroom/student_work/activity）
- `description`: 图片描述（可选）
- `sort_order`: 排序权重

**业务规则**:
- 图片必须上传
- 类型必须选择
- 每种类型最多50张图片
- 自动按 sort_order 升序排列
- 前端展示时按类型分组显示

**用户故事**:
```
作为机构管理员
我想上传教室环境照片和学员作品
以便让家长了解我们的教学条件和教学效果
```

##### 3.1.5.3 教师团队管理

**需求描述**: 机构可以展示教师团队信息，增强家长信任。

**功能要点**:
- 添加教师（上传头像、填写姓名、职称、简介、标签）
- 编辑教师信息
- 删除教师
- 排序调整（拖拽排序）
- 查看教师列表

**数据字段**:
- `name`: 教师姓名
- `title`: 职称（如"高级钢琴教师"、"金牌教练"）
- `avatar_url`: 头像URL
- `tags`: 标签数组（如["5年教龄", "耐心负责", "获奖教师"]）
- `bio`: 个人简介（教学经历、获奖经历等）
- `user_id`: 关联系统用户ID（可选，用于后期扩展教师端功能）
- `sort_order`: 排序权重

**业务规则**:
- 教师姓名必填
- 头像建议上传，可选
- 标签最多6个
- 简介不超过500字
- 支持最多50个教师
- 自动按 sort_order 升序排列

**用户故事**:
```
作为机构管理员
我想添加机构教师的信息和照片
以便让家长了解我们的师资力量
```

**注意**:
> ⚠️ **关于教师数据**：
> - `institution_teachers`: 机构展示用的教师介绍（营销目的，在创建机构时一起填写）
> - `teachers`: 系统统一管理的教师资源（用于排课，在机构添加完成后单独添加，挂在机构下）
> - 两者是不同的数据表，服务于不同的业务场景

### 3.2 课程管理模块

#### 3.2.1 课程发布

**需求描述**: 机构可以发布课程，设置课程信息和价格规格。

**功能要点**:
- 填写课程基本信息（标题、副标题、简介、详情）
- 上传课程封面图和轮播图（最多9张）
- 选择课程分类（三级分类）
- 选择课程类型（正式课 / 试听课）
- 设置适龄范围（最小年龄 - 最大年龄）
- 添加课程标签（多选）
- 设置课程SKU（多规格）
  - SKU名称（如"10课时包"、"20课时包"）
  - 总课时数
  - 课程总价
  - 返现类型（百分比 / 固定金额 / 无）
  - 返现值（根据类型填写）
  - 库存（-1表示不限）

**业务规则**:
- 机构必须审核通过才能发布课程
- 课程标题不可为空
- 封面图必须上传
- 至少添加一个SKU
- 返现金额由后端自动计算：
  ```
  固定返现: 线上支付 = 返现金额，线下支付 = 总价 - 返现金额
  百分比返现: 线上支付 = 总价 × 返现比例，线下支付 = 总价 - 线上支付
  无返现: 线上支付 = 总价，线下支付 = 0
  ```
- 课程发布后默认为下架状态，需要手动上架

**用户故事**:
```
作为机构管理员
我想发布一个钢琴课程，设置10课时和20课时两种规格
以便家长可以根据需求选择购买
```

#### 3.2.2 课程列表与搜索

**需求描述**: 家长可以浏览课程列表，通过筛选和搜索找到合适的课程。

**功能要点**:
- 查看课程列表（支持分页）
- 按分类筛选（三级分类）
- 按类型筛选（正式课 / 试听课）
- 按适龄范围筛选
- 按距离排序（基于位置）
- 按价格排序
- 按销量排序
- 按评分排序
- 关键字搜索（课程标题）

**业务规则**:
- 仅显示已上架的课程
- 仅显示已审核通过机构的课程
- 默认按创建时间倒序

#### 3.2.3 课程详情

**需求描述**: 家长可以查看课程详细信息，了解课程内容、价格、机构等。

**展示内容**:
- 课程基本信息（标题、副标题、封面、轮播图）
- 课程详情（富文本描述）
- 适龄范围、标签
- 课程SKU列表（课时、价格、返现信息）
- 所属机构信息（名称、Logo、地址、联系方式）
- 课程评价列表（评分、评论、图片）
- 平均评分
- 销量统计

**交互功能**:
- 选择SKU
- 立即购买
- 预约试听
- 收藏课程（预留）
- 分享课程（预留）

#### 3.2.4 课程管理（机构侧）

**需求描述**: 机构可以管理自己发布的课程。

**功能要点**:
- 查看课程列表（支持分页、筛选）
- 编辑课程信息
- 上架/下架课程
- 删除课程（软删除）
- 查看课程统计（销量、评分、预约数）

**业务规则**:
- 有未完成订单的课程不可删除
- 下架后家长不可见，但不影响已购买用户
- 编辑课程不影响已生成的订单（订单使用快照）

### 3.3 资源管理模块

#### 3.3.1 教室管理

**需求描述**: 机构可以管理教室资源，用于排课。

**功能要点**:
- 创建教室（名称、容量、面积、楼层）
- 设置教室设施（投影仪、空调、钢琴等，多选）
- 设置教室状态（可用 / 维护中 / 已停用）
- 编辑教室信息
- 删除教室（软删除）
- 排序管理（拖拽排序）

**业务规则**:
- 教室名称在同一机构内不可重复
- 有未完成排课的教室不可删除
- 维护中和已停用的教室不可用于排课

#### 3.3.2 教师管理

**需求描述**: 机构可以管理教师档案，用于排课和展示。

**功能要点**:
- 创建教师档案（姓名、性别、联系方式、头像）
- 设置擅长科目（多选）
- 填写教学经验（年限、简介）
- 上传教师证书（多张图片）
- 设置教师状态（在职 / 离职 / 休假）
- 编辑教师信息
- 删除教师（软删除）
- 排序管理

**业务规则**:
- 教师姓名在同一机构内不可重复
- 有未完成排课的教师不可删除
- 离职和休假状态的教师不可用于排课

#### 3.3.3 排课管理

**需求描述**: 机构可以为课程安排上课时间、教师和教室。

**功能要点**:
- 创建排课（选择课程、教师、教室）
- 设置上课时间（开始时间 - 结束时间）
- 设置星期几（1-7，1表示周一）
- 设置最大学生数
- 编辑排课
- 删除排课（软删除）
- 查看排课列表（按课程/教师/教室/时间筛选）
- 冲突检测
  - 同一教师在同一时间段不能有多个排课
  - 同一教室在同一时间段不能有多个排课

**业务规则**:

- 已预约人数达到最大学生数后不可再预约
- 有预约记录的排课不可删除
- 开始时间必须早于结束时间

### 3.5 订单管理模块

#### 3.5.0 订单状态说明 ⭐

**订单状态枚举**:

| 状态 | 英文标识 | 说明 |
|------|---------|------|
| 待支付 | `pending` | 订单已创建，等待用户支付 |
| 待确认 | `pending_confirm` | 线上支付成功，等待机构确认（正式课） |
| 已确认 | `confirmed` | 机构已确认，订单生效，用户可在课表查看 |
| 待退款审核 | `refund_pending` | 用户申请退款，等待机构审核 |
| 退款中 | `refunding` | 机构同意退款，退款处理中（微信退款等） |
| 退款被拒 | `refund_rejected` | 机构拒绝退款申请 |
| 已退款 | `refunded` | 退款已完成 |
| 已取消 | `cancelled` | 订单已取消（用户主动取消或超时取消） |
| 已完成 | `completed` | 课程已完成，可以评价 |

**订单状态流转图**:

```

                                    │           用户下单                  │
                                    └─────────────────┬───────────────────┘
                                                      ▼
                                              ┌───────────────┐

                                              │   (待支付)    │
                                              └───────┬───────┘
                         ┌────────────────────────────┼────────────────────────────┐
                         │                            │                            │

**状态流转规则**:

1. **用户下单** → `pending`（待支付）
2. **线上支付成功**:
   - **体验课（trial）**: `pending` → `confirmed`（自动确认，预约也自动确认）
   - **正式课（standard）**: `pending` → `pending_confirm`（待确认）
3. **机构确认订单**: `pending_confirm` → `confirmed`（预约自动确认）
4. **用户申请退款**: `confirmed` → `refund_pending`（待退款审核）
5. **机构处理退款**:
   - 同意: `refund_pending` → `refunding`（退款处理中）
   - 拒绝: `refund_pending` → `refund_rejected`（退款被拒）
6. **退款完成**: `refunding` → `refunded`（退款成功，关联预约中未签到的自动取消）
7. **退款被拒后**: `refund_rejected` 状态下用户可再次申请退款 → `refund_pending`
8. **课程完成**: `confirmed` → `completed`（所有课时签到完毕自动完成）
9. **用户取消订单**: `pending` → `cancelled`（仅待支付状态可取消，关联预约自动取消）
10. **线下支付确认**: `pending` → `confirmed`（直接生效）
11. **订单超时**: `pending` → `cancelled`（30分钟未支付自动取消）

**关键业务说明**:
- ⭐ **体验课不需要机构确认**：线上支付成功后系统自动确认，降低机构操作成本
- ⭐ **正式课需要机构确认**：线上支付成功后进入待确认状态，机构确认后订单生效
- ⭐ **订单确认后预约自动确认**：订单变为 `confirmed` 后，关联的预约状态也自动变为 `confirmed`
- ⭐ **只有已确认状态才能申请退款**：`pending_confirm` 状态的订单不能申请退款
- ⭐ **退款审核分两步**：先进入 `refund_pending` 等待机构审核，同意后进入 `refunding` 处理退款
- ⭐ **退款被拒可重新申请**：`refund_rejected` 状态下用户可再次申请退款
- ⭐ **退款/取消时关联预约处理**：订单退款或取消时，关联的未签到预约（pending/confirmed）自动取消，已签到的（completed）不受影响
- ⭐ **用户课表显示规则**：只有 `confirmed` 状态的订单对应的预约才会显示在用户课表中

#### 3.5.5 退款流程

**需求描述**: 家长可以申请退款，机构审核处理。

**退款流程**:
```
1. 家长申请退款（填写退款原因）
   ↓ 订单状态: confirmed → refunding
2. 机构审核退款申请
   ↓ 同意 → 处理退款 → refunded（已退款）
   ↓ 拒绝 → confirmed（已确认，恢复原状态）
```

**退款金额计算**:
- **全额退款**: 未开始上课，退款金额 = 实付金额
- **部分退款**: 已上部分课程，按比例退款
  ```
  退款金额 = 实付金额 - (已上课时数 × 单课时价格)
  单课时价格 = 实付金额 / 总课时数
  ```

**业务规则**:
- 仅**已确认**状态可以申请退款
- 待确认状态不可申请退款
- 已完成订单不可退款
- 退款申请提交后48小时内机构必须处理，否则自动同意
- 退款成功后 SKU 库存 +1

#### 3.5.6 上课签到 ⭐

**需求描述**: 家长可以为已预约的课程进行上课签到，类似钉钉打卡。签到后系统自动扣除课时。

**功能要点**:
- 钉钉风格的圆形签到按钮（点击触发签到）
- 显示当前日期和时间
- 显示课程信息（课程名称、机构名称）
- 显示上课进度（已上X课/共Y课）
- 签到成功后显示本次签到信息
- 支持历史补卡（选择日期进行补签）
- 上课前24小时内可签到（开发模式下可跳过此限制）

**签到规则**:
- 每节课（预约）只能签到一次
- 重复签到提示"这节课已经签到过了"
- 签到成功后 `completed_lessons` +1
- 当 `completed_lessons` = `total_lessons` 时，订单自动标记为已完成
- **签到是按预约（booking）级别的**，一个订单可以有多个预约，每个预约对应一节课

**24小时限制**:
- 生产环境：只有上课前24小时内才能签到
- 开发环境（ENV=development）：跳过24小时限制，方便测试

**补卡规则**:
- 只能补过去日期的签到
- 未来日期不可补卡
- 已签到日期不可重复补卡
- 补卡需要填写备注（原因）

**订单课时管理**:
- `total_lessons`: 总课时数（来自 SKU 的 lesson_count）
- `completed_lessons`: 已完成课时数（签到次数）
- 订单列表显示进度条：`已上 X 课 / 共 Y 课`

**业务规则**:
- 仅 `confirmed`（已确认）状态的预约可以签到
- 签到必须关联预约ID（booking_id）
- 签到记录包含：订单ID、预约ID、排课ID、签到时间、是否补卡、课时序号
- 签到记录可选记录经纬度（用于位置验证，预留）
- 所有课时签到完成后，订单自动变为 `completed`

**用户故事**:
```

### 3.7 用户管理模块

#### 3.7.1 家长用户登录

**需求描述**: 家长使用微信小程序一键登录。

**登录流程**:
```
1. 用户点击"微信登录"按钮
2. 小程序调用 wx.login() 获取 code
3. 前端将 code 发送给后端
4. 后端调用微信接口用 code 换取 openid
5. 查询用户是否存在
   - 存在: 直接生成 JWT Token
   - 不存在: 创建新用户，生成 JWT Token
6. 返回 Token 给前端
7. 前端存储 Token，完成登录
```

**业务规则**:
- 使用 openid 作为用户唯一标识
- 首次登录自动创建用户记录
- JWT Token 有效期7天
- Token 过期后需要重新登录

#### 3.7.2 机构用户登录

**需求描述**: 机构使用用户名密码登录。

**登录流程**:
```
1. 输入用户名和密码
2. 后端验证用户名和密码
3. 查询用户关联的机构
4. 生成 JWT Token（包含机构ID）
5. 返回 Token 和机构信息
```

**业务规则**:
- 密码使用 bcrypt 加密存储
- 连续5次登录失败锁定账号10分钟（预留）
- 机构被冻结后无法登录

#### 3.7.3 用户信息管理

**需求描述**: 用户可以查看和编辑个人信息。

**功能要点**:

## 7. 接口需求

### 7.1 RESTful API 规范

#### 7.1.1 请求格式
- 使用 JSON 格式
- Content-Type: application/json
- Authorization: Bearer {token}

#### 7.1.2 响应格式
```json
{
  "code": 200,
  "message": "success",
  "data": {
    // 响应数据
  }
}
```

#### 7.1.3 状态码规范

| 状态码 | 说明 | 场景 |
|-------|------|------|
| 200 | 成功 | 请求成功 |
| 400 | 参数错误 | 参数校验失败 |
| 401 | 未授权 | Token无效或过期 |
| 403 | 无权限 | 没有操作权限 |
| 404 | 资源不存在 | 找不到资源 |
| 500 | 服务器错误 | 内部错误 |

#### 7.1.4 分页格式
```json
{
  "data": [...],
  "total": 100,
  "page": 1,
  "pageSize": 20,
  "totalPages": 5
}
```

## 9. 风险与对策

### 9.1 技术风险

| 风险 | 可能性 | 影响 | 对策 |
|------|-------|------|------|
| 并发性能瓶颈 | 中 | 高 | 使用Redis缓存、数据库读写分离 |
| 数据库查询慢 | 中 | 中 | 添加索引、优化查询、使用分页 |
| 文件存储成本 | 高 | 中 | 使用OSS存储、图片压缩、CDN加速 |
| 第三方接口不稳定 | 低 | 高 | 添加重试机制、熔断降级 |

### 9.2 业务风险

| 风险 | 可能性 | 影响 | 对策 |
|------|-------|------|------|
| 机构入驻意愿低 | 中 | 高 | 提供免费试用期、降低入驻门槛 |
| 家长用户留存率低 | 中 | 高 | 优化用户体验、增加营销活动 |
| 恶意评价/刷单 | 中 | 中 | 评价审核机制、订单风控 |
| 退款纠纷 | 中 | 中 | 明确退款政策、客服介入处理 |

### 9.3 安全风险

| 风险 | 可能性 | 影响 | 对策 |
|------|-------|------|------|
| 账号被盗 | 低 | 高 | 短信验证、异常登录检测 |
| 数据泄露 | 低 | 高 | 数据加密、权限控制、日志审计 |
| SQL注入攻击 | 低 | 高 | 使用ORM参数化查询、输入校验 |
| DDoS攻击 | 低 | 中 | 使用CDN、限流、黑名单 |

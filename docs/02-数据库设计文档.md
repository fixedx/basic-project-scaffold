## 1. 数据库概述

### 1.1 设计原则

1. **统一基础字段**: 所有表继承 BaseEntity 的通用字段
2. **应用层关联**: 不使用外键约束，关联关系在应用层处理
3. **软删除机制**: 使用 `is_delete` 字段标记删除，不物理删除
4. **雪花ID**: 使用16位雪花ID作为主键，保证分布式唯一性
5. **UTC 时间**: 所有时间字段使用 UTC 时区
6. **JSONB 存储**: 灵活数据使用 JSONB 类型，支持索引和查询
7. **枚举统一管理**: 枚举数据统一存储在 enums 表，避免硬编码

### 1.2 命名规范

| 对象 | 规范 | 示例 |
|------|------|------|
| 表名 | 小写 + 下划线 | `users`, `course_skus` |
| 字段名 | 小写 + 下划线 | `user_id`, `created_at` |
| 索引名 | `idx_表名_字段名` | `idx_courses_institution_id` |
| 唯一索引 | `uk_表名_字段名` | `uk_users_openid` |

### 1.3 数据库统计

- **表数量**: 25张核心业务表
- **视图数量**: 0
- **存储过程**: 0
- **触发器**: 0（使用应用层处理）

```
┌─────────────┐
│   users     │ 统一用户表（家长 + 机构账号）
└──────┬──────┘
       │

┌──────────────────┐

└────────┬─────────┘
         │

         ↓
┌────────────────┐      1:N      ┌──────────┐
│ institutions   │ ←──────────── │ courses  │ 课程表
└────────────────┘               └────┬─────┘
         │                            │
         │ 1:N                        │ 1:N
         ↓                            ↓
┌────────────────┐               ┌─────────────┐
│   classrooms   │ 教室表        │ course_skus │ 课程SKU表
└────────────────┘               └─────────────┘
         │
         │ 1:N
         ↓
┌────────────────┐      N:1      ┌───────────┐
│   teachers     │ ←──────────── │ schedules │ 排课表
└────────────────┘               └─────┬─────┘
                                       │
                                       │ 1:N
                                       ↓
                                 ┌──────────┐
                                 │ bookings │ 预约表
                                 └──────────┘

┌──────────┐      N:1      ┌─────────┐
│  orders  │ ←──────────── │ reviews │ 评价表
└──────────┘               └─────────┘

┌──────────┐
│ banners  │ Banner表（独立）
└──────────┘

┌──────────┐
│  enums   │ 枚举表（独立）
└──────────┘

┌──────────────┐
│ categories   │ 分类表（三级分类）
└──────────────┘
```

### 2.2 关系说明

| 关系 | 说明 |
|------|------|
| users ↔ user_institutions ↔ institutions | 用户与机构多对多关系（通过中间表） |
| institutions → courses | 一个机构有多个课程 |
| courses → course_skus | 一个课程有多个SKU |
| institutions → classrooms | 一个机构有多个教室 |
| institutions → teachers | 一个机构有多个教师 |
| courses + teachers + classrooms → schedules | 排课关联课程、教师、教室 |
| schedules → bookings | 一个排课有多个预约 |
| users + courses → orders | 用户购买课程生成订单 |
| orders → reviews | 订单完成后可以评价 |

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|--------|------|------|--------|------|

#### 3.4.2 course_skus（课程SKU表）

**表名**: `course_skus`  
**说明**: 课程价格规格（如10课时包、20课时包）

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|--------|------|------|--------|------|
| **[BaseEntity字段]** | | | | |
| course_id | VARCHAR(16) | NOT NULL | | 课程ID |
| name | TEXT | NOT NULL | | SKU名称（如"10课时包"） |
| total_lessons | INTEGER | NOT NULL | | 总课时数 |
| total_price | DECIMAL(10,2) | NOT NULL | | 课程总价 |
| cashback_type | TEXT | NOT NULL | 'none' | 返现类型（percentage-比例, fixed-固定, none-无） |
| cashback_value | DECIMAL(10,2) | | 0 | 返现值 |
| online_pay_price | DECIMAL(10,2) | | 0 | 线上支付金额（后端计算） |
| offline_pay_price | DECIMAL(10,2) | | 0 | 线下支付金额（后端计算） |
| stock | INTEGER | | -1 | 库存（-1表示不限） |
| sort | INTEGER | | 0 | 排序 |

**索引**:
```sql
CREATE INDEX idx_course_skus_course_id ON course_skus(course_id) WHERE is_delete = false;
CREATE INDEX idx_course_skus_sort ON course_skus(course_id, sort ASC) WHERE is_delete = false;
```

**返现计算逻辑**（后端自动计算）:
```sql
-- 固定返现
CASE 
  WHEN cashback_type = 'fixed' THEN
    online_pay_price = cashback_value
    offline_pay_price = total_price - cashback_value
    
-- 百分比返现
  WHEN cashback_type = 'percentage' THEN
    online_pay_price = total_price * (cashback_value / 100)
    offline_pay_price = total_price - online_pay_price
    
-- 无返现
  ELSE
    online_pay_price = total_price
    offline_pay_price = 0
END
```

## 4. 索引设计

### 4.1 索引策略

1. **主键索引**: 所有表的 `id` 字段自动创建主键索引
2. **唯一索引**: 唯一字段（如 `openid`, `order_no`）创建唯一索引
3. **外键字段**: 关联字段（如 `institution_id`, `course_id`）创建普通索引
4. **查询条件**: 常用查询条件（如 `status`, `type`）创建索引
5. **排序字段**: 常用排序字段（如 `sort`, `created_at`）创建索引
6. **位置搜索**: 经纬度字段创建组合索引
7. **软删除过滤**: 所有索引都加上 `WHERE is_delete = false` 条件

## 6. 数据库规范

### 6.1 字段类型规范

| 数据类型 | PostgreSQL类型 | 说明 |
|---------|---------------|------|
| 字符串 | TEXT | 统一使用 TEXT，不用 VARCHAR |
| 整数 | INTEGER | 小整数用 INTEGER，大整数用 BIGINT |
| 小数 | DECIMAL(10,2) | 金额统一用 DECIMAL |
| 布尔 | BOOLEAN | true/false |
| 时间 | TIMESTAMP WITH TIME ZONE | UTC时间，带时区 |
| JSON | JSONB | 支持索引和查询 |

### 6.2 命名规范

1. **表名**: 小写 + 下划线，复数形式（如 `users`, `courses`）
2. **字段名**: 小写 + 下划线（如 `user_id`, `created_at`）
3. **索引名**: 
   - 普通索引: `idx_表名_字段名`
   - 唯一索引: `uk_表名_字段名`
4. **避免使用SQL关键字**作为表名或字段名

### 6.3 约束规范

1. **主键**: 所有表使用 `id VARCHAR(16)` 作为主键
2. **非空约束**: 必填字段添加 `NOT NULL`
3. **唯一约束**: 唯一字段添加 `UNIQUE` 或创建唯一索引
4. **默认值**: 尽量设置合理的默认值
5. **不使用外键约束**: 关联关系在应用层处理

### 6.4 注释规范

```sql
COMMENT ON TABLE users IS '统一用户表（家长+机构）';
COMMENT ON COLUMN users.openid IS '微信openid（家长用户）';
COMMENT ON COLUMN users.username IS '用户名（机构用户）';
```

## 7. 性能优化

### 7.1 查询优化

#### 7.1.1 位置搜索优化

**使用 PostGIS + `distance_km()` 计算距离**:
```sql
SELECT *,
  distance_km(location, :userLng, :userLat) AS distance
FROM institutions
WHERE is_delete = false
  AND audit_status = 'approved'
  AND location IS NOT NULL
HAVING distance < :radius
ORDER BY distance ASC
LIMIT :limit;
```

#### 7.1.2 分页查询优化

**使用游标分页**（适合大数据量）:
```sql
-- 第一页
SELECT * FROM courses
WHERE is_delete = false
ORDER BY id DESC
LIMIT 20;

-- 后续页（使用上一页最后一条记录的ID）
SELECT * FROM courses
WHERE is_delete = false
  AND id < :lastId
ORDER BY id DESC
LIMIT 20;
```

#### 7.1.3 避免N+1查询

**批量查询关联数据**:
```sql
-- ❌ 错误：逐个查询（N+1问题）
SELECT * FROM courses WHERE id = ?;
SELECT * FROM course_skus WHERE course_id = ?; -- 执行N次

-- ✅ 正确：批量查询
SELECT * FROM courses WHERE id IN (...);
SELECT * FROM course_skus WHERE course_id IN (...); -- 执行1次
```

### 7.2 索引优化

#### 7.2.1 复合索引

**查询条件顺序要匹配索引**:
```sql
-- 创建复合索引
CREATE INDEX idx_courses_institution_type_online 
ON courses(institution_id, type, is_online) 
WHERE is_delete = false;

-- ✅ 能使用索引
SELECT * FROM courses 
WHERE institution_id = ? AND type = ? AND is_online = true;

-- ❌ 不能完全使用索引（跳过了 institution_id）
SELECT * FROM courses 
WHERE type = ? AND is_online = true;
```

#### 7.2.2 部分索引

**使用 WHERE 条件减少索引大小**:
```sql
-- 只索引未删除的数据
CREATE INDEX idx_courses_title 
ON courses(title) 
WHERE is_delete = false;

-- 只索引已上架的课程
CREATE INDEX idx_courses_online 
ON courses(created_at DESC) 
WHERE is_delete = false AND is_online = true;
```

### 7.3 查询缓存

**使用Redis缓存热点数据**:
- 首页Banner列表（缓存10分钟）
- 推荐课程列表（缓存5分钟）
- 课程详情（缓存30分钟）
- 枚举数据（缓存1小时）

## 8. 备份与恢复

### 8.1 备份策略

#### 8.1.1 全量备份

**每天凌晨3点执行**:
```bash
#!/bin/bash
# backup-db.sh
DATE=$(date +%Y%m%d)
BACKUP_FILE="interest_class_$DATE.sql"

pg_dump -U postgres -h localhost -d interest_class > /backup/$BACKUP_FILE
gzip /backup/$BACKUP_FILE

# 保留最近30天的备份
find /backup -name "interest_class_*.sql.gz" -mtime +30 -delete
```

#### 8.1.2 增量备份

**使用PostgreSQL的WAL归档**:
```sql
-- postgresql.conf
wal_level = replica
archive_mode = on
archive_command = 'cp %p /backup/wal/%f'
```

### 8.2 恢复策略

#### 8.2.1 完全恢复

```bash
# 1. 停止应用服务
systemctl stop interest-class-server

# 2. 删除现有数据库
psql -U postgres -c "DROP DATABASE interest_class;"

# 3. 创建新数据库
psql -U postgres -c "CREATE DATABASE interest_class;"

# 4. 恢复数据
gunzip -c /backup/interest_class_20260117.sql.gz | psql -U postgres -d interest_class

# 5. 启动应用服务
systemctl start interest-class-server
```

#### 8.2.2 时间点恢复（PITR）

```bash
# 恢复到某个时间点
pg_basebackup -D /restore -Fp -Xs -P -U postgres
# 配置 recovery.conf
restore_command = 'cp /backup/wal/%f %p'
recovery_target_time = '2026-01-17 10:00:00'
```

### 8.3 灾难恢复

1. **主从复制**: 使用PostgreSQL流复制实现主从同步
2. **异地备份**: 备份文件同步到异地存储（阿里云OSS）
3. **定期演练**: 每月进行一次恢复演练
4. **监控告警**: 备份失败及时告警
